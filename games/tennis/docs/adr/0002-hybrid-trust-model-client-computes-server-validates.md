# Hybrid trust model: client computes hits, server only validates legality

Within tennis's Authoritative Room (see root [ADR-0001](../../../docs/adr/0001-relay-vs-authoritative-multiplayer-rooms.md)), the server doesn't re-derive hit trajectories from scratch. Each client computes its own hit/serve locally — reusing the existing hand-tracking/gesture/physics code unchanged — and reports the resulting velocity and spin. The server only validates *whether* a hit or serve is currently legal (ball state, whose turn), then takes over continuous ball simulation from that reported point onward. Each client also still runs its own racket-vs-ball collision detection locally purely for rendering the opponent's paddle responsively; the server doesn't use that local result for anything.

This is a deliberate cheat-vs-latency trade-off, not full server-side re-simulation: a malicious client could still misreport a hit's velocity/spin within legal bounds, but re-deriving hit physics server-side from raw hand-tracking data was judged not worth the added latency and complexity for this game. Worth knowing explicitly, since "Authoritative Room" alone could otherwise be read as "server re-simulates everything from raw input."
